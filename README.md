# بوت المحقق - نسخة مجموعات ماسنجر (FCA)

⚠️ **تحذير**: هذه واجهة غير رسمية تخالف شروط استخدام فيسبوك. قد يُقفل الحساب أو يطلب checkpoint في أي وقت.
استخدم **حساباً مخصصاً للبوت فقط** (وليس حسابك الشخصي)، وبرقم/إيميل تقدر تسترجعه.

## التشغيل
1. `npm install` (يتطلب Node.js 20 أو أحدث؛ يمكن تغيير `FCA_MODULE` في `.env` لاختيار مكتبة FCA أخرى)
2. ثبّت وشغّل MySQL 8+ أو MariaDB، واضبط بيانات الاتصال في `.env` (`DB_HOST` و`DB_PORT` وبيانات المستخدم).
3. انسخ `.env.example` إلى `.env` واملأه، ثم أنشئ قاعدة البيانات والجداول عبر `npm run db:setup`. يجب أن تكون خدمة MySQL قيد التشغيل قبل تنفيذ الأمر.
4. صدّر كوكيز حساب البوت (بإضافة متصفح مثل c3c-fbstate) إلى `appstate.json` بجانب `server.js`
5. `npm start` ثم أضف حساب البوت إلى مجموعة ماسنجر

### النشر على Bot-Hosting.net (Messenger)

1. أنشئ **Application deployment** واختر Runtime من نوع Node.js، ثم اربط مستودع GitHub أو ارفع أرشيف المشروع. ارفع `package.json` و`package-lock.json` وملفات المصدر، ولا ترفع `node_modules` أو `.env` أو ملفات الجلسة والنسخ الاحتياطية. يثبّت Bot-Hosting اعتمادات Node.js من `package.json`.
2. من إعدادات **Startup** اجعل **Entry File** هو `server.js` وأمر التشغيل `npm start`. يتطلب المشروع Node.js 20 أو أحدث (`engines` في `package.json`).
3. أنشئ حساباً وخطة TiDB Cloud Starter المجانية من [صفحة TiDB Cloud](https://www.pingcap.com/tidb/cloud/)، وأنشئ قاعدة `detective_bot` من SQL Editor إذا لم تكن موجودة (`CREATE DATABASE detective_bot;`). من صفحة **Connect** انسخ بيانات الاتصال كما هي إلى متغيرات **Environment** في Bot-Hosting: `DB_HOST` و`DB_PORT` و`DB_USER` و`DB_PASSWORD` و`DB_NAME`. عيّن `DB_CREATE_DATABASE=0` و`DB_SSL=1`؛ لا تستخدم `127.0.0.1`. إذا أعطتك صفحة الاتصال شهادة CA، ضع محتواها في `DB_SSL_CA` مع إبقاء التحقق من الشهادة مفعّلاً.
4. أضف من **Environment** أيضاً `LOGIN_MODE=appstate` و`APPSTATE_PATH=./appstate.json`. ارفع `appstate.json` الصالح بشكل منفصل من تبويب **Files**، واجعل ملف الجلسة ومجلد الحالة `.nexca` محفوظين ضمن ملفات النشر. إذا كانت الجلسة مشفّرة، أضف قيمة `APPSTATE_ENCRYPTION_KEY` نفسها إلى البيئة. لا تضع الأسرار في Git أو في أرشيف الرفع.
5. ابدأ التطبيق، ثم نفّذ `npm run db:setup` مرة واحدة من **Shell** بعد بدء النشر وتأكد من نجاحه؛ بعدها أعد تشغيل التطبيق. أضف مفاتيح الخدمات الاختيارية من **Environment** حسب الميزات المطلوبة. إعدادات `admin-ids.json` اختيارية، ويمكن إنشاؤها من `admin-ids.example.json`.

راجع دليل [إنشاء نشر](https://bot-hosting.net/docs/guides/create-a-deployment) و[إعداده](https://bot-hosting.net/docs/guides/set-up-a-deployment). الخطة المجانية المعلنة في Bot-Hosting تسمح بنشر واحد فقط؛ استخدام TiDB Cloud كقاعدة خارجية يتجاوز الحاجة إلى نشر قاعدة بيانات ثانية على Bot-Hosting، مع مراعاة حصة TiDB المجانية وحدود موارد التطبيق (256 MB RAM و512 MB مساحة على خطة Bot-Hosting المجانية). لا حاجة إلى فتح منفذ عام للألعاب الأساسية؛ لعبة الرسم والروابط العامة للصور تحتاج إعداد نطاق/منفذ متوافقاً مع الاستضافة.

احتفظ بملفات الحالة وقاعدة البيانات بعد إعادة التشغيل وإعادة النشر. لا يلزم فتح منفذ عام لتشغيل الألعاب الأساسية؛ لعبة الرسم والروابط العامة للصور تحتاج منفذ `SPY_IMAGE_PORT` مخصصاً ورابطاً عاماً أو نفقاً صالحاً، وقد تتطلب تثبيت `cloudflared` أو `tailscale` داخل البيئة. يوفّر السيرفر منفذ HTTP محلياً فقط ولا ينشئ رابط HTTPS عاماً تلقائياً.

### اختيار مكتبة FCA

يستطيع `FCA_MODULE` اختيار مكتبة واحدة لكل تشغيل: `@dongdev/fca-unofficial` أو `fca-azadx69x` أو `facebook-chat-api` (حزمة `fbapi-unofficial` المستضافة على GitHub). الحزمتان الأوليان من npm، أما `facebook-chat-api` فتُثبّت من مستودع GitHub المحدد في `package.json`. غيّر قيمة `FCA_MODULE` في `.env` إلى اسم المكتبة المراد استخدامها؛ لا تُشارك `appstate.json` عند تبديلها. تتطلب `fbapi-unofficial` إصدار Node.js 22.23.2 أو أحدث؛ المكتبتان الأخريان تعملان مع حد المشروع الأدنى الحالي (Node.js 20). كل هذه المكتبات غير رسمية، وقد تؤدي محاولة الدخول إلى طلب تحقق أو تقييد الحساب.

ميزة المحادثة الذكية اختيارية وتعمل أونلاين عبر Cloudflare Workers AI افتراضياً؛ طريقة الإعداد موضحة أدناه. مفتاح `GEMINI_API_KEY` مخصص للصور، أو للقضايا إذا اخترت `CRIME_AI_PROVIDER=gemini`. فعّل المحادثة داخل محادثة بأمر `/تكلم`، وأوقفها بـ`/اسكت`. في المجموعات لا يمكن تشغيلها أو إيقافها إلا للأدمن. ترد جود عند مناداتها باسمها أو الرد على رسالة منها، لكنها تترك الرسائل للألعاب أثناء وجود جولة نشطة حتى لا تعترض أوامرها. تعمل الميزة أيضاً في نسخة Telegram، وحالتها منفصلة لكل منصة ومحادثة.

### محادثة الذكاء الاصطناعي أونلاين

تعمل ميزة `/تكلم` عبر **Cloudflare Workers AI** من دون تثبيت نموذج على جهاز البوت. أنشئ رمز API يسمح باستخدام Workers AI، ثم ضع `CLOUDFLARE_ACCOUNT_ID` و`CLOUDFLARE_API_TOKEN` في `.env` لـMessenger أو `.env.telegram` لـTelegram (إذا كانا يعملان معاً، أضف الإعدادات إلى الملفين). رمز API سرّي ولا يُشارك أو يُرفع إلى Git. النموذج الافتراضي `@cf/openai/gpt-oss-20b` ويمكن تغييره عبر `CLOUDFLARE_AI_MODEL`. توفّر الخطة المجانية 10,000 Neurons يومياً للحساب، وتُصفّر الحصة عند 00:00 UTC؛ يختلف عدد الرسائل الفعلي بحسب طول سياق الشات والقضايا، وقد تتجاوز الاستخدامات العالية الحصة. راقب الاستهلاك من [لوحة Workers AI](https://dash.cloudflare.com/?to=/:account/ai/workers-ai) وراجع [الأسعار والحدود](https://developers.cloudflare.com/workers-ai/platform/pricing/) و[واجهة Chat Completions المتوافقة](https://developers.cloudflare.com/workers-ai/configuration/open-ai-compatibility/). يستخدم الشات والقضايا الإعدادات نفسها افتراضياً؛ يمكن تغيير كل منهما على حدة عبر `AI_CHAT_PROVIDER` و`CRIME_AI_PROVIDER`. يبقى Groq متاحاً اختيارياً بضبط القيمة إلى `groq` وتعبئة `GROQ_API_KEY`.

شخصية **جود** أنثوية سعودية بعمر 18 سنة، وتتحدث بلهجة سعودية عامية؛ وهذا طابع متخيّل لشخصية ذكاء اصطناعي، لا ادعاء بأنها إنسانة أو صاحبة تجارب حقيقية. هي ذكية وسريعة الفطنة ومرحة، تمزح بلطف وتتوقف إذا بدا أن أحداً تضايق، وتكون دافئة ومفيدة عند جدية الموضوع. كل ردودها يولّدها النموذج؛ لا ترد على الرسائل العادية، وتتوقف أثناء وجود لعبة نشطة في المجموعة أو إذا كان المرسل مشاركاً في لعبة نشطة في الخاص. تقرأ سياق محادثتها معها فقط، ويمكنها فهم الرد على رسالة من رسائلها السابقة. قد ترسل ردها كرسالتين أو ثلاث كما يفعل البشر. يُحفظ سياق المحادثة مؤقتاً في الذاكرة فقط ويُمسح عند إيقاف الميزة أو إعادة تشغيل البوت، وتمنع الميزة معالجة معرّف الرسالة نفسه مرتين. يمكن تخصيص الشخصية عبر `AI_CHAT_PERSONA`. عند مناداة جود أو الرد على رسالتها، تُرسل الرسالة وسياق محادثتها إلى مزوّد الذكاء الاصطناعي السحابي المختار.

### مساعد التصاميم

أوامر مساعد التصاميم مستقلة: `قوالب` لعرض القوالب، `اقتراح <فكرة>` لاقتراح اتجاه بصري، `وصف <فكرة>` لكتابة وصف لمولّد الصور، `تحسين <وصف>` لتحسين الوصف أو تحليل صورة مرجعية، `توليد <وصف>` لإنشاء صورة، `منشور <الموضوع>` لكتابة نص جاهز لفيسبوك وإنشاء صورة مربعة، و`قالب <اسم القالب> <الفكرة>` لاستخدام قالب محدد. اكتب `مساعدة_التصميم` لعرض القائمة. نص المنشور يُرسل منفصلاً عن الصورة لتفادي أخطاء كتابة النص داخل الصورة. لتعديل صورة مع الحفاظ على تصميمها، أرفقها أو ردّ عليها بـ`تعديل <التغيير>`؛ ولإنشاء صورة جديدة مستوحاة من الصورة المرجعية، ردّ عليها بـ`توليد <الوصف>` أو `منشور <الموضوع>`. ما زالت الصيغ القديمة مثل `تصميم منشور <الموضوع>` و`تصميم تعديل <التغيير>` مدعومة. أمر تحسين الجودة مستقل عن مساعد التصاميم: ردّ على الصورة واكتب `جودة`، وسيحمّلها البوت ويكبّرها 4× باستخدام Upscayl/Real-ESRGAN محلياً، دون إرسالها إلى Cloudflare. يتطلب المحرك بطاقة رسومية وتعريفاً يدعمان Vulkan؛ تنتهي المحاولة بعد دقيقتين وقد تختلف التوافقية والسرعة حسب البطاقة، خصوصاً الرسوميات المدمجة. حزمة `upscayl-node` المستخدمة مرخصة AGPL-3.0. تعمل ميزات النص وتوليد/تعديل الصور عبر Cloudflare Workers AI وتتطلب `CLOUDFLARE_ACCOUNT_ID` و`CLOUDFLARE_API_TOKEN`، ويُستخدم نموذج الصور `@cf/black-forest-labs/flux-2-dev` افتراضياً ويمكن تغييره عبر `CLOUDFLARE_DESIGN_IMAGE_MODEL`، كما يمكن تغيير نموذج الرؤية عبر `CLOUDFLARE_DESIGN_VISION_MODEL`. عند فشل توليد الصور أو نفاد حصة Cloudflare، يستخدم البوت [AI Horde](https://stablehorde.net/) كبديل مجاني؛ أنشئ مفتاح API مجاني واضبطه في `AI_HORDE_API_KEY`. تعتمد الخدمة على طابور متطوعين وقد يستغرق التوليد عدة دقائق أو يفشل عند غياب العمال، وينتهي الانتظار بعد 8 دقائق. عند تفعيل البديل، يُرسل الوصف والصورة المرجعية إلى AI Horde وعماله المتطوعين؛ لا تستخدم صوراً حساسة. صور Cloudflare المرجعية يجب أن تكون PNG أو JPEG وألا تتجاوز 5 ميغابايت؛ تُصغّر إلى 512 بكسل كحد أقصى. استخدم صوراً تملك حق استخدامها؛ القوالب مصممة لشخصيات أصلية ولا تنسخ شعارات أو شخصيات أعمال محمية.

لإنشاء مقطع إيديت أنمي قصير، ردّ على صورة تملك حق استخدامها بالأمر `ايديت`؛ يستخدم هذا الأمر Fal.ai مع Kling 2.5 Turbo Pro، ويتطلب `FAL_KEY` وقد تُحتسب تكلفة على حساب Fal.ai. أما الأمر المستقل `فيديو` (أو `حرك`) فيرسل الصورة إلى Hugging Face ZeroGPU Space عام لتحريكها؛ أضف `HF_TOKEN` اختيارياً و`HF_IMAGE_TO_VIDEO_SPACE_URL` إلى `.env` للاستفادة من حصة مجانية محدودة، مع احتمال الانتظار في الطابور أو توقف الخدمة. الصورة تُرسل إلى Space تابع لطرف ثالث؛ لا تستخدم صوراً حساسة، واقصر الاستخدام على صور تملك حق استخدامها. الحد الأقصى للصورة 5 ميغابايت وللفيديو الناتج 25 ميغابايت. عند استخدام Space مختلف، يجب أن يكون رابط HTTPS أساسياً ضمن نطاق `.hf.space`.

### تشغيل نسخة Telegram

1. انسخ `.env.telegram.example` إلى `.env.telegram`، وأنشئ بوتاً عبر `@BotFather` وضع `TELEGRAM_BOT_TOKEN` فيه، ثم ضع رقم حسابك الرقمي في `TELEGRAM_OWNER_ID`.
2. شغّل `npm run db:setup:telegram` مرة واحدة لإنشاء قاعدة Telegram المنفصلة، ثم ابدأ البوت بـ`npm run start:telegram`.
3. أضف البوت إلى المجموعة وسجّل بزر «انضمام إلى اللعبة»؛ لا يلزم بدء محادثة خاصة لتشغيل اللعب. سيحاول البوت إرسال الرسائل الخاصة مباشرة، لكن Telegram لا يسمح بإيصالها إلا بعد أن يضغط اللاعب `/start` أو يراسل البوت أولاً.
4. بعض الألعاب تحتاج قراءة إجابات نصية داخل المجموعة. عطّل **Group Privacy** للبوت من BotFather أو اجعله مشرفاً، ثم أزل البوت وأعد إضافته للمجموعة كي يطبّق Telegram الإعداد. إذا كان البوت يرد في الخاص فقط، فتأكد أنه ما زال عضواً وغير مقيّد من إرسال الرسائل في المجموعة؛ يسجل البوت سبب رفض Telegram في سجل التشغيل. وإذا تحولت المجموعة إلى supergroup، يعيد البوت توجيه الإرسال تلقائياً إلى معرّف المجموعة الجديد بعد أول محاولة.

تستخدم نسخة Telegram ملف `.env.telegram` وطبقة إرسال ومسارات حالة خاصة بها، وتعمل بمخططات قاعدة بيانات مستقلة عن Messenger؛ كما لا تحمّل اتصال FCA الخاص بماسنجر. محركات الألعاب تبقى مشتركة بين المنصتين حتى تتلقى النسختان إصلاحات اللعب نفسها. عند تشغيل Telegram وMessenger على الجهاز نفسه، يستخدم Telegram منفذ رسم محلياً `3101` وTailscale Funnel على `8443` افتراضياً، مقابل منافذ Messenger الأصلية. لا تشغّل أكثر من نسخة Telegram واحدة بالتوكن نفسه؛ واجهة long polling لا تعمل بالتزامن مع نسخة أخرى أو webhook. للتشغيل المستمر استخدم مدير عمليات/مهمة بدء تشغيل على جهاز يبقى متصلاً، مع تشغيل MySQL.

إذا ظهر `login_blocked` أو checkpoint، أوقف البوت ولا تكرر محاولات تسجيل الدخول أو تعدّل ملفات الجلسة. راجع تنبيهات أمان الحساب مباشرة لدى Facebook؛ لا تشارك `appstate.json` أو نسخه الاحتياطية. يعتمد هذا المشروع على FCA غير رسمي وغير مدعوم من Meta؛ للتكامل المستقر استخدم واجهات Meta الرسمية.

عند استخدام `hridoy-fca`، يوقف ملف `fca-config.json` التحديث التلقائي للحزمة لتجنب تغييرات غير متوقعة أثناء تشغيل البوت.

يمكن إرسال صور لعبة الجاسوس كرابط مؤقت عبر `SPY_IMAGE_DELIVERY=host` لتفادي قيود مرفقات الخاص المشفّر. ولإرسال الرابط والمرفق المباشر معاً، استخدم `SPY_IMAGE_DELIVERY=both` وفعّل `FCA_E2EE_NATIVE_DM_IMAGES=1` مع إبقاء `FCA_E2EE_NATIVE=0`. مسار المرفق الأصلي تجريبي وقد يفصل اتصال أحد أجهزة الحساب؛ عند فشله يبقى رابط الصورة المؤقت بديلاً. استخدمه فقط مع حساب البوت، وأعد `FCA_E2EE_NATIVE_DM_IMAGES` إلى `0` إذا ظهرت مشكلة في الجلسة. يمكن فحص المسارين عبر `/spytest` في الخاص.

## بنية الألعاب

تضيف لعبة «من أي فيلم كرتون؟» جولة تخمين مقتطفات أفلام من ملف `games/cartoonMovies/quotes.json`؛ لا تُرفق اللعبة حوارات جاهزة، ويضيف المشرف محتوى يملك حق استخدامه. لعبتا الإيموجي في `games/emojiGuess/` و`games/emojiFilm/` تقدمان ألغازاً أصلية، وتستخدم لعبة أفلام الإيموجي أسماء الأفلام الموجودة في ملف البيانات فقط.

البوت هو نقطة الاتصال الوحيدة مع Messenger، وكل لعبة وحدة مستقلة (modular service) يوجّه إليها مدير الألعاب الرسائل والتفاعلات والمؤقّتات. الألعاب لا تعمل كعمليات أو خوادم إضافية. ملفات لعبة مين قتل كريم موجودة في `games/crime/`، وملفات إمبراطورية STORM في `games/storm/`، وملفات لعبة الجاسوس في `games/spy/`، وملفات فيجن في `games/feign/`، وملفات المستذئب في `games/werewolf/`، وملفات الرسم والتخمين في `games/drawing/`، والألعاب السريعة الجديدة في `games/quote/` و`games/ordering/` و`games/wordmarket/`، ومزاد كرة القدم في `games/footballAuction/`، ولعبة «أكمل الأغنية» (نسخة سبيستون) في `games/spacetoon/` وتحتاج أن تضيف الأغاني بنفسك في `games/spacetoon/songs.json` (التفاصيل في `games/spacetoon/README.md`)؛ أضيف الأمر `/العاب` لعرض الألعاب المتاحة. الملفات العامة مثل `database.js` و`services/messenger.js` و`server.js` تبقى مشتركة بين الألعاب. صور افتتاح التسجيل للعبتي مين قتل كريم وSTORM معطّلة حالياً، وتُرسل رسالة التسجيل كنص فقط. تظل صورة الجولة السرية في لعبة الجاسوس مفعّلة لأنها جزء من اللعب؛ وتُحفظ مع صور الجاسوس في جدول `game_image_cache` داخل MySQL لإعادة استخدامها بعد إلغاء اللعبة أو إعادة تشغيل البوت. عند بدء التشغيل، ينشئ كل محرك لعبة جداولها المفقودة تلقائياً من `schema.sql` الموجود في مجلدها؛ كما يحمّل `npm run db:setup` مخططات جميع الألعاب.

### أوامر البوت العامة

اكتب الأوامر مباشرة دون `/`؛ الصيغة التي تبدأ بـ`/` ما زالت مقبولة للتوافق.
استخدم الصيغ المقروءة ذات المسافات، مثل `/الألعاب` و`/قواعد جاسوس` و`/تشغيل لعبة`؛ تبقى الأسماء القديمة الملتصقة أو التي تستخدم `_` مدعومة للتوافق.

الأوامر التالية تعمل في المجموعات والخاص، حتى عند وجود لعبة نشطة: `/مساعدة` أو `/الأوامر` لعرض قائمة البوت والألعاب، `/شرح <اسم اللعبة>` لعرض قواعد وأوامر أي لعبة (مثل `/شرح الجاسوس` أو `/شرح الرسم`)، `/العاب` لعرض الألعاب المتاحة، `/ترتيب النقاط` أو `/التصنيف` أو `/leaderboard` لعرض أعلى 10 لاعبين بالنقاط، `/نقاطي` لعرض نقاطك، و`/ping` للتأكد أن البوت يستقبل الأوامر. متجر النقاط: `متجر` لعرض السلع ورصيدك، `شراء <رقم>` للشراء، `مقتنياتي` لعرض السلع المملوكة، و`لقب <رقم>` لتفعيل لقب تملكه. تُحفظ عمليات الشراء والخصم في سجل النقاط كي لا تُعاد النقاط المصروفة عند إعادة احتساب النتائج بعد تشغيل البوت. ألقاب المتجر تظهر في الترتيب وعند عرض نقاط اللاعب؛ عناصر المزايا تُحفظ في المخزون، ويُضاف تأثيرها داخل الألعاب عند تعريف المزايا. عند كتابة `/شرح` وحده، يعرض شرح اللعبة الافتراضية «مين قتل كريم». تبقى أوامر الشرح الخاصة بكل لعبة متاحة أيضاً، مثل `/قواعدجاسوس` و`/قواعدرسم`، وتُعرض أسماء هذه الأوامر عند إدخال اسم لعبة غير معروف. رسائل التسجيل توضح طريقة الانضمام والحد الأدنى والمهلة؛ تبدأ الألعاب المسجلة تلقائياً عند انتهاء المهلة إذا اكتمل الحد الأدنى، وإلا تُلغى. النقاط تختلف حسب صعوبة اللعبة: الرسم نقطة، الجاسوس نقطتان، التحقيق وSTORM والمستذئب 3 نقاط، وفيجن 4 نقاط. في الرسم يحصل الرسام والمخمّن الصحيح على قيمة الجولة. تُحفظ النقاط في قاعدة البيانات ولا يتكرر احتساب الفوز، كما يُعاد احتساب سجل النقاط السابق تلقائياً وفق القيم الجديدة عند تشغيل البوت. الأمر `/صلاحياتي` يعرض صلاحيات مرسل الأمر وحالة حظره. الأمر العام `/الغاء` أو `/إلغاء` أو `/cancel` يلغي اللعبة النشطة في المجموعة؛ للمضيف أو أدمن البوت.
الأوامر التالية تعمل في المجموعات والخاص، حتى عند وجود لعبة نشطة: `/مساعدة` أو `/الأوامر` لعرض قائمة البوت والألعاب، `/شرح <اسم اللعبة>` لعرض قواعد وأوامر أي لعبة (مثل `/شرح الجاسوس` أو `/شرح الرسم`)، `/العاب` لعرض الألعاب المتاحة، `/ترتيب النقاط` أو `/التصنيف` أو `/leaderboard` لعرض أعلى 10 لاعبين بالنقاط، `/نقاطي` لعرض نقاطك، و`/ping` للتأكد أن البوت يستقبل الأوامر. متجر النقاط: `متجر` لعرض السلع ورصيدك، `شراء <رقم>` للشراء، `مقتنياتي` لعرض السلع المملوكة، و`لقب <رقم>` لتفعيل لقب تملكه. تُحفظ عمليات الشراء والخصم في سجل النقاط كي لا تُعاد النقاط المصروفة عند إعادة احتساب النتائج بعد تشغيل البوت. ألقاب المتجر تظهر في الترتيب وعند عرض نقاط اللاعب؛ عناصر المزايا تُحفظ في المخزون، ويُضاف تأثيرها داخل الألعاب عند تعريف المزايا. عند كتابة `/شرح` وحده، يعرض شرح اللعبة الافتراضية «مين قتل كريم». تبقى أوامر الشرح الخاصة بكل لعبة متاحة أيضاً، مثل `/قواعدجاسوس` و`/قواعدرسم`، وتُعرض أسماء هذه الأوامر عند إدخال اسم لعبة غير معروف. رسائل التسجيل توضح طريقة الانضمام والحد الأدنى والمهلة؛ تبدأ الألعاب المسجلة تلقائياً عند انتهاء المهلة إذا اكتمل الحد الأدنى، وإلا تُلغى. النقاط تختلف حسب صعوبة اللعبة: الرسم نقطة، الجاسوس نقطتان، التحقيق وSTORM والمستذئب 3 نقاط، وفيجن 4 نقاط. في الرسم يحصل الرسام والمخمّن الصحيح على قيمة الجولة. الألعاب الجديدة تمنح نقطة للفائز. تُحفظ النقاط في قاعدة البيانات ولا يتكرر احتساب الفوز، كما يُعاد احتساب سجل النقاط السابق تلقائياً وفق القيم الجديدة عند تشغيل البوت. الأمر `/صلاحياتي` يعرض صلاحيات مرسل الأمر وحالة حظره. الأمر العام `/الغاء` أو `/إلغاء` أو `/cancel` يلغي اللعبة النشطة في المجموعة؛ للمضيف أو أدمن البوت.

أوامر التحكم بالألعاب والبوت متاحة لمالك البوت فقط ومن الخاص: `/تشغيل لعبة <اسم اللعبة>` و`/إيقاف لعبة <اسم اللعبة>`، و`/حالة الألعاب` لعرض حالتها. استخدم `/إيقاف البوت` لإيقاف الردود والألعاب مؤقتًا مع إبقاء اتصال Messenger قائمًا، ثم `/تشغيل البوت` لاستئناف العمل. أما `/إغلاق البوت` فينهي العملية بالكامل؛ بعده شغّل البوت من لوحة الاستضافة. يستطيع الأدمن إضافة رد محفوظ عبر `/رد أضف <محفز> | <الرد>`، حذفه عبر `/رد احذف <محفز>`، وعرض الردود عبر `/الردود الثابتة`. يطابق البوت المحفز ككلمة أو عبارة مستقلة في الرسائل العادية خارج الألعاب النشطة، وتُحفظ الإعدادات في MySQL.

عند انضمام عضو جديد إلى مجموعة Messenger أو Telegram، ترحب به جود برسالة قصيرة وتعرّفه بأمر عرض الألعاب.

البحث عن صور Pinterest متاح في Messenger وTelegram: اكتب `بنترست <وصف الصورة> [العدد]`؛ يرسل البوت الصور الأولى غير المكررة من النتائج، والعدد الافتراضي صورة واحدة. عند طلب أكثر من صورة، يرسلها معاً في رسالة واحدة على Messenger أو كألبوم واحد على Telegram. يتجنب إعادة إرسال الدبوس أو ملف الصورة نفسه أثناء تشغيل البوت، حتى مع اختلاف بسيط في وصف البحث، ثم ينتقل إلى النتائج التالية. يمكن ضبط الحد الأقصى وحدود الاستخدام من إعدادات `PINTEREST_*` في ملفات البيئة النموذجية.

البحث عن أعمال DeviantArt متاح عبر الواجهة الرسمية: اكتب `صورة <وسم> [العدد]`، مثل `صورة فن رقمي` أو `صورة 3 قطط`؛ وتبقى الصيغة القديمة `ديفينت آرت <وسم> [العدد]` مدعومة. يعتمد الأمر على استعراض الوسوم الرسمية (وليس البحث النصي الحر)، ويرسل معاينات الأعمال كصور مع اسم الفنان ورابط العمل، مع استبعاد الأعمال المصنّفة ناضجة. الأمر المجرد `/صورة` في الخاص يبقى مخصصاً لاختبار إرسال الصور. يتطلب تسجيل تطبيق خادمي من [بوابة مطوري DeviantArt](https://www.deviantart.com/developers/register) بصلاحية `browse`، ثم إضافة `DEVIANTART_CLIENT_ID` و`DEVIANTART_CLIENT_SECRET` محلياً في ملف البيئة؛ لا تشارك السر أو ترفعه إلى Git. تفاصيل [المصادقة الرسمية](https://deviantart.readme.io/docs/authentication) و[واجهة الوسوم](https://deviantart.readme.io/reference/browse_tags).

في مجموعات Messenger فقط، يمكن الرد على رسالة لاعب آخر بـ`قتل` أو `تهكير` لعرض المؤثرات، ثم يرسل البوت مباشرة `Just kidding`. عطّلها عبر `FUN_COMMANDS_ENABLED=0`، واضبط مهلة الخطوات عبر `FUN_HACK_STEP_DELAY_MS`.

### الألعاب الجديدة

- **من صاحب العبارة:** اكتب `عبارة` لتخمين صاحب مقولة تاريخية. أول إجابة صحيحة تحصل على نقطة.
- **من أي فيلم كرتون؟:** اكتب `كرتون` لتخمين الفيلم من مقتطف تضيفه بنفسك إلى `games/cartoonMovies/quotes.json` وتملك حق استخدامه. اللعبة لا تتضمن حوارات جاهزة؛ تفاصيل التنسيق في `games/cartoonMovies/README.md`.
- **خمن الإيموجي من الوصف:** اكتب `خمن الإيموجي`، وأرسل الإيموجي الموصوف بأسرع ما يمكن.
- **احزر الشخصية (أنمي):** اكتب `احزر الشخصية` واسأل أي سؤال إجابته نعم أو لا، أو خمّن الاسم مباشرة. تستخدم اللعبة Cloudflare Workers AI مع إعدادات `CLOUDFLARE_ACCOUNT_ID` و`CLOUDFLARE_API_TOKEN` الموضحة أعلاه؛ لا تحتاج إلى Google Search أو مفتاح بحث منفصل.
- **خمن فيلم كرتون من الإيموجي:** اكتب `فيلم إيموجي` (والاختصار `افلام` ما زال مقبولاً) لتخمين عنوان موجود في ملف أفلام الكرتون من لغز إيموجي.
- **تحدي الترتيب:** اكتب `ترتيب` ورتّب العناصر كما يطلب السؤال. تتغير التحديات ولا تتكرر في المجموعة حتى تُستنفد القائمة.
- **سوق الكلمات:** اكتب `سوق الكلمات` ثم أرسل كلمة من الفئة تبدأ بالحرف الذي يختاره البوت. أول إجابة صحيحة تفوز، والتحديات لا تتكرر قبل استنفاد القائمة.
- **مزاد كرة القدم:** اكتب `مزاد` وانتظر لاعباً ثانياً يكتب `انضمام`. يبدأ كل لاعب برصيد افتراضي 100، ويزايد الاثنان على لاعبي كرة القدم حتى يكوّن كل منهما تشكيلة من خمسة لاعبين؛ بعدها يحاكي البوت مباراة خيالية ويمنح الفائز نقطة. أوامر المزايدة: `رشح <رقم>`، `زايد <مبلغ>`، `مرر`. هذا الرصيد خاص باللعبة ولا يُخصم من نقاط المتجر.
- **البحث عن الكنز:** اكتب `البحث عن الكنز` (أو `كنز`) وسجّل بالتفاعل مع رسالة التسجيل، ثم اكتشف الأدلة المتتابعة واجمع المفاتيح لفتح الصندوق النهائي.
- **سوق الظلال:** اكتب `سوق الظلال` لبدء لعبة تفاوض بأدوار وعقود سرية. تفاوضوا علناً وأرسلوا عروض القطع وقبولها للبوت في الخاص؛ بينكم مهرّب ومفتش، وتُكشف الأدوار والبطاقات عند النهاية.
- **شفرة الإنقاذ:** اكتب `شفرة الإنقاذ` لتتعاونوا على كسر ثلاثة أقفال؛ يحصل كل لاعب على دليل سري مختلف، وتتشاركون الأدلة في المجموعة قبل انتهاء الوقت.

لاختبار إرسال صورة، أرسل `/صورة` أو `/اختبارصورة` للبوت في الخاص.

### صلاحيات الأدمن والحظر

مالك البوت هو «لايت» (معرّف Messenger: `61555344774852`) وله رتبة ثابتة أعلى من الأدمن؛ لا يمكن حظره أو تنزيل رتبته. انسخ `admin-ids.example.json` إلى `admin-ids.json` بجانب `server.js`، ثم أضف معرّفات Messenger كقيم نصية داخل `adminIds` (مثال: `{"adminIds":["123456789"]}`) وأعد تشغيل البوت. الملف الحقيقي مستثنى من Git؛ لا تضع فيه إلا المعرّفات الموثوقة. إذا لم يوجد الملف أو كانت القائمة فارغة، لا يوجد أدمن إضافي غير مالك البوت.

أوامر الأدمن، في المجموعة أو الخاص: `/ادمن` لعرض الأوامر، `حالة_الاتصال` لفحص تسجيل دخول حساب Messenger واستقبال الرسائل وحالة E2EE عند دعمها، `/حظر <معرّف> [السبب]` لحظر مستخدم من بدء الألعاب والتسجيل فيها، `/فكحظر <معرّف>` لرفع الحظر، و`/المحظورين` لعرض القائمة. إدارة المتجر للأدمن: `متجر إضافة <لقب|ميزة> <السعر> | <الاسم> | <الوصف>`، `متجر حذف <رقم>`، `متجر سعر <رقم> <السعر>`، و`متجر وصف <رقم> | <الوصف>`. حذف السلعة يخفيها من المتجر ولا يلغي ما اشتراه اللاعبون. عناصر المزايا تُضاف إلى مخزون اللاعب دون أثر داخل اللعبة حتى تعريف أثرها. يقتصر رفع الأدمن `/رفع ادمن` أو `/رفع ادمن <المعرّف>` وتنزيله `/تنزيل ادمن` بالرد على رسالته أو `/تنزيل ادمن <المعرّف>` على مالك البوت؛ تُحفظ التغييرات فوراً في `admin-ids.json`. لا يستطيع الأدمن رفع أو تنزيل أدمن آخر. الحظر دائم ويشمل كل الألعاب حتى رفعه؛ لا يخرج المحظور من مباراة بدأت قبل الحظر. يستطيع الأدمن إلغاء لعبة نشطة بأي مجموعة باستخدام `/الغاء` داخلها، بينما يظل الإلغاء مقصوراً على المضيف لبقية المستخدمين.

مالك البوت وحده يستطيع إيقاف لعبة مؤقتاً وإعادة تشغيلها: `/تعطيل لعبة <اسم اللعبة>` أو `/تفعيل لعبة <اسم اللعبة>`، مثلاً `/تعطيل لعبة الجاسوس` و`/تفعيل لعبة الجاسوس`. يعرض `/حالة_الألعاب` حالة كل الألعاب. حالة الإيقاف تُحفظ في قاعدة البيانات وتستمر بعد إعادة تشغيل البوت؛ تمنع بدء مباريات جديدة، بينما تُترك المباريات النشطة لتكمل، ويمكن تشغيل اللعبة مجدداً في أي وقت.

صور افتتاح التسجيل للعبتي التحقيق وSTORM معطّلة حالياً؛ تُرسل رسالة التسجيل كنص، من دون توليد صورة عبر Gemini. تسجيل لعبة الجاسوس أيضاً رسالة نصية فقط؛ لا تُجهّز صورة الجولة إلا بعد اكتمال التسجيل وبدء اللعب، ثم تُرسل بشكل خاص للاعبين دون الجاسوس لأنها جزء أساسي من الجولة. إذا جُهّز المشهد ثم فشل بدء الجولة، يُحفظ في جدول `spy_pending_scenes` ويُعاد استخدامه في الجولة التالية التي تبدأ بنجاح. يلزم ضبط `PIXABAY_API_KEY` (أو `GEMINI_API_KEY` كبديل) في `.env`. يضع البوت رابط Pixabay في رسائل اللعبة للإشارة إلى مصدر الصور.

لإضافة لعبة لاحقاً، أنشئ مجلداً باسمها داخل `games/` وضع ملفاتها وإعداداتها وخدماتها ومخطط جداولها الخاص فيه؛ صدّر من `index.js` تعريفاً يحتوي `id` و`name` و`startCommand` و`startAliases` و`commandAliases` ومحركاً يوفّر `handleMessage` و`handleReaction` و`startTicker`. أضف تعريف اللعبة إلى قائمة التسجيل في `services/gameManager.js`. يمكن للمحرك تنفيذ `canHandleMessage` الاختيارية للتعرّف على رسائل الخاص للاعبين الحاليين. يجب أن تكون معرفات الألعاب وأوامرها فريدة؛ يتحقق مدير الألعاب من ذلك عند التشغيل. استخدم لكل لعبة إعداداتها وجداولها الخاصة، وسجّل `game_id` في `game_rooms` كي يوجّه البوت أحداث المجموعة والتفاعلات إلى اللعبة الصحيحة. يسمح المخطط الحالي بلعبة نشطة واحدة لكل مجموعة في الوقت نفسه. تُرحّل الغرف القديمة تلقائياً إلى `crime` عند تشغيل البوت.

### لعبة حاول تهرب

ابدأ في المجموعة بكتابة `حاول تهرب` أو `/حاول_تهرب`؛ لا يُسجل منشئ اللعبة تلقائياً، والانضمام من 4 إلى 5 لاعبين بالتفاعل مع رسالة التسجيل مثل بقية الألعاب. يختار البوت قاضياً عشوائياً ويبقى القاضي نفسه حتى نهاية اللعبة. يرسل القاضي سؤال الجولة في الخاص مع البوت، ثم يرسل كل متسابق في الخاص أسوأ إجابة تخطر بباله. يخلط البوت الإجابات ويوزعها على المتسابقين دون أن تصل إجابة لصاحبها؛ يتناوبون في المجموعة على تبرير الإجابة التي وصلت إليهم خلال 30 ثانية لكل لاعب. بعد ذلك يختار القاضي من يخرج بكتابة `/استبعادتهرب <رقم أو اسم>`. تتكرر الجولات حتى يبقى متسابق واحد، ويحصل الفائز على نقطة. مهلة إرسال السؤال 5 دقائق، والإجابات دقيقتان، وقرار القاضي 3 دقائق. الأوامر: `/قواعدحاولتهرب` و`/حالةتهرب` و`/خروجتهرب` و`/إلغاءتهرب`.

### البحث عن الكنز

ابدأ في المجموعة بكتابة `كنز`، ثم تفاعل مع رسالة التسجيل للانضمام (3–8 لاعبين، والمضيف لا يُسجل تلقائياً). يتبع اللاعبون مساراً من أربعة أدلة إلى مواقع مختلفة؛ أول إجابة صحيحة في كل مرحلة تحصل على مفتاح، ولا يرسل البوت رداً على الإجابات الخاطئة. يوجد تلميح واحد مشترك لكل دليل؛ أول لاعب يطلبه بكتابة `تلميحكنز` يدفع مفتاحاً، ويحتاج مفتاحين على الأقل. بعد الدليل الرابع يظهر لغز القفل النهائي، ويتنافس حاملو المفاتيح المتبقية على فتح الصندوق؛ وإذا لم يجمع أحد مفاتيح يحق للجميع المحاولة. إذا لم يُفتح الصندوق في الوقت المحدد، يفوز صاحب أكبر عدد من المفاتيح، ويُمنح المتعادلون نقطة لكل منهم. مهلة التسجيل دقيقة، وكل دليل دقيقة، والقفل النهائي 90 ثانية. الأوامر: `قواعدالكنز` و`حالةالكنز` و`خروجالكنز` و`إلغاءالكنز` و`تلميحكنز`.

### سوق الظلال

ابدأ في المجموعة بكتابة `سوق الظلال`، ثم تفاعل مع رسالة التسجيل للانضمام (4–8 لاعبين، والمضيف لا يُسجل تلقائياً). تستمر اللعبة ثلاث جولات؛ في كل جولة يحصل كل لاعب على بطاقة سرية، ولكل لاعب 10 عملات. تفاوضوا في المجموعة، ثم أرسلوا للبوت في الخاص `عرض <رقم اللاعب> <السعر> | <وصف القطعة>`؛ يقبل المستلم أو يرفض العرض في الخاص (`قبول <رقم العرض>` أو `رفض <رقم العرض>`). يوجد مهرّب يحمل بطاقات مزيفة ومفتش يستطيع فحص بطاقة لاعب واحدة في كل جولة (`فحص <رقم اللاعب>` في الخاص)، بينما يملك بقية التجار عقوداً سرية مختلفة. تبقى حقيقة البطاقة مخفية حتى نهاية اللعبة؛ تُحتسب العملات وقيمة البطاقات الأصلية والمكافآت السرية، ويحصل الفائز أو المتعادلون على نقطة. كل جولة 90 ثانية والتسجيل دقيقة. الأوامر: `قواعدالظلال` و`حالةالظلال` و`حقيبةالظلال` و`خروجالظلال` و`إلغاءالظلال`.

### شفرة الإنقاذ

ابدأ في المجموعة بكتابة `شفرة الإنقاذ`، ثم تفاعل مع رسالة التسجيل للانضمام (4–6 لاعبين، والمضيف لا يُسجل تلقائياً). يحصل كل لاعب على دليل مختلف في الخاص؛ شاركوا الأدلة في المجموعة لحل الرمز، المكوّن من أربعة أرقام مختلفة من 1 إلى 9، مع كون الرقم الأيسر أكبر في كل زوج متجاور. أرسلوا التخمين في المجموعة بصيغة `رمز <أربعة أرقام>`؛ يكشف البوت بعد المحاولة الخاطئة عدد الأرقام الصحيحة ومواقعها. أمام الفريق خمسة تخمينات و90 ثانية لكل قفل، وعليه فتح ثلاثة أقفال ليفوز كل المشاركين بنقطة. الأوامر: `قواعدالإنقاذ` و`حالةالإنقاذ` و`معلومةالإنقاذ` و`خروجالإنقاذ` و`إلغاءالإنقاذ`.

### إمبراطورية STORM

ابدأها في المجموعة بكتابة `ستورم` أو `/ستورم` والتفاعل مع رسالة التسجيل. تقبل 4-8 لاعبين، وتُرسل الأدوار والقدرات الخاصة في الخاص؛ يجري اللعب بالتناوب بين الليل والنهار والتصويت. تتغير تشكيلة الأدوار عشوائياً مع الحفاظ على عدد الظلال وتوازن اللعبة، كما يُخلط ترتيب توزيعها على اللاعبين. لتفعيل قدرة ليلية أو التصويت، يجب الرد على بطاقة البوت المناسبة؛ لا تُقبل الأوامر المباشرة. عند خروج لاعب أثناء الليل أو إقصائه بالتصويت، يعلن البوت دوره. يربح المخادع نقطة عندما يغيّر صوته نتيجة الإقصاء، ويمكنه شراء الدروع بـ3 ثم 5 ثم 7 نقاط؛ لا تحمي الدروع من التصويت.

لإضافة شعار STORM إلى صورة ملفك الشخصي، ردّ على الصورة بأمر `/شعار`. يمكنك تحديد موضع الشعار بإضافة المكان، مثل `/شعار أسفل المنتصف` أو `/شعار أعلى اليمين`؛ يدعم البوت تسعة مواضع حول الصورة، ويتحقق من بقائها داخل دائرة القص الآمنة. ينتج البوت صورة مربعة عالية الدقة (1024x1024).

يمكن تفعيل تحليل ذكي لموضع الشعار عبر `STORM_LOGO_AI_ANALYSIS=1` مع إعداد `CLOUDFLARE_ACCOUNT_ID` و`CLOUDFLARE_API_TOKEN`. يستخدم التحليل نموذج Cloudflare `@cf/meta/llama-3.2-11b-vision-instruct` (يمكن تغييره عبر `STORM_LOGO_AI_MODEL`) ويرسل معاينة مربعة منخفضة الدقة إلى Cloudflare لاختيار منطقة خالية أو موضع زينة شعر للشخصية ذات المظهر الأنثوي؛ يبقى حجم الشعار ثابتاً. عند تحديد المستخدم للموضع، يُعتمد اختياره ولا تُرسل الصورة إلى Cloudflare للتحليل. الإعداد معطّل افتراضياً، وعند فشل التحليل التلقائي يُستخدم الموضع الافتراضي مع تنبيه. يتطلب النموذج موافقة أولية على ترخيص Meta عبر Cloudflare قبل استخدامه؛ راجع [توثيق النموذج](https://developers.cloudflare.com/workers-ai/models/llama-3.2-11b-vision-instruct/).

لا يرسل البوت رسائل ترحيب خاصة أثناء التسجيل إلا بعد اكتمال الحد الأدنى من اللاعبين (4 افتراضياً)، ويرسل الترحيب مرة واحدة لكل لاعب.

### لعبة الجاسوس

ابدأ اللعبة في المجموعة بكتابة `جاسوس`، ثم تفاعلوا مع رسالة التسجيل النصية (3-8 لاعبين افتراضياً). لا يلزم إرسال رسالة للبوت قبل الانضمام؛ لكن الأدوار والصور السرية تصل في الخاص، وقد يمنع Messenger وصولها أو يضعها في طلبات الرسائل. بعد اكتمال التسجيل، يختار البوت مشهداً عشوائياً من قائمة مناسبة لجميع الأعمار، ويبحث عن صورة له في Pixabay؛ يرسلها كمرفق خاص لكل لاعب عدا الجاسوس، الذي يتلقى تلميحاً نصياً فقط. لا تُرسل الصورة إلى المجموعة. يلزم إنشاء [مفتاح Pixabay API](https://pixabay.com/api/docs/) وإضافته إلى `PIXABAY_API_KEY` في `.env`، أو ضبط `GEMINI_API_KEY` لاستخدام صور مولّدة كبديل. إذا تعذّر بدء الجولة بعد تجهيز الصورة، يحتفظ بها البوت في قاعدة البيانات لاستخدامها في الجولة الناجحة التالية. لاختبار تجهيز الصورة وإرسالها إلى حسابك الخاص دون إنشاء مباراة، أرسل `/spytest` أو `/اختبارجاسوس` للبوت في الخاص. تُحفظ الصور في قاعدة البيانات لإعادة استخدامها بعد إلغاء اللعبة أو إعادة تشغيل البوت، ويُذكر مصدر Pixabay برابط في رسائل اللعبة. يصف اللاعبون الصورة في المجموعة دون ذكر عنوانها أو كلماتها المفتاحية؛ من يذكر كلمة ممنوعة يخسر وحده ويُستبعد. بعد النقاش يصوّت اللاعبون سراً بالرد على بطاقة التصويت الخاصة في الخاص برقم اللاعب أو اسمه؛ لا يُقبل أمر تصويت مباشر. وإذا أُقصي الجاسوس، يحصل على 30 ثانية ومحاولة واحدة لتخمين عنوان الصورة أو إحدى كلماتها المفتاحية بالرد على بطاقة التخمين الخاصة؛ لا يُقبل التخمين بأمر مباشر. الأوامر: `/قواعدجاسوس` و`/spyplayers` و`/spyleave` و`/spycancel`. يمكن ضبط أعداد اللاعبين ومؤقتات التسجيل والنقاش والتصويت بمتغيرات `SPY_MIN_PLAYERS` و`SPY_MAX_PLAYERS` و`SPY_LOBBY_SECONDS` و`SPY_DISCUSSION_SECONDS` و`SPY_VOTING_SECONDS`. عدد اللاعبين مضبوط افتراضياً بين 3 و8، وحده الأعلى 8. تُضاف جداول اللعبة تلقائياً عند تشغيل البوت، أو عبر `npm run db:setup`.

### لعبة الرسم والتخمين

ابدأ اللعبة بكتابة `رسم` في المجموعة لتكون أنت الرسام، أو أرسل الأمر بالرد على رسالة اللاعب الذي تريده أن يرسم. يوجد رسام واحد فقط في اللعبة، وبقية المجموعة تخمّن. يجهز البوت صفحة الرسم ويتحقق من الرابط الخاص بالجولة قبل إرساله للرسام، لتكون الصفحة جاهزة عند فتحها. ارسم باللمس أو الماوس، وتُرفع الرسمة تلقائياً كل 30 ثانية. لا تُلغى اللعبة لمجرد توقف الرسام عن الرسم؛ يمكنه إنهاؤها بزر «إلغاء الجولة» في الصفحة، وتبقى مدة الجولة القصوى خمس دقائق من بدء الرسم. تعرض الصفحة عدّاداً مستقلاً لوقت الإرسال القادم. صلاحية رابط الرسم 3 ساعات كحد أقصى، ما دام البوت والجولة يعملان. الصفحة مناسبة للهاتف وتوفر تغيير اللون والحجم، والممحاة، والتراجع، ومسح اللوحة. اللعبة جولة واحدة فقط وتنتهي عند التخمين الصحيح أو انتهاء مدتها، ثم تتوقف حتى يبدأ أحدهم لعبة جديدة؛ لا يؤدي تكرار أمر `/رسم` أثناء الجولة إلى إنشاء كلمة إضافية.

إذا كان `SPY_IMAGE_PUBLIC_BASE_URL` فارغاً، يحاول البوت بدء [Tailscale Funnel](https://tailscale.com/docs/features/tailscale-funnel) تلقائياً، ثم يستخدم Cloudflare Quick Tunnel كبديل. يراقب البوت الرابط العام كل `DRAWING_TUNNEL_WATCHDOG_SECONDS` ثانية (60 افتراضياً)، ويعيد محاولة الاتصال عند انقطاعه. اضبطه إلى `0` لتعطيل المراقبة، أو `DRAWING_TUNNEL_FALLBACK=0` لمنع الانتقال إلى Cloudflare. تتطلب أنفاق Tailscale اتصالاً بالإنترنت وتفعيل HTTPS وMagicDNS وFunnel لحساب tailnet؛ يستخدم البوت المنفذ المحدد في `TAILSCALE_FUNNEL_PORT` ويوقف المسار الذي أنشأه عند انتهاء آخر لعبة رسم. المسارات الموجودة مسبقاً لا يوقفها البوت. استخدم `DRAWING_TUNNEL_KEEP_ALIVE=1` لإبقاء Funnel الذي أنشأه البوت بعد انتهاء اللعبة.

لإعداد Funnel دائم وتثبيت عنوانه في `.env`، شغّل `setup-drawing-url.bat` يدوياً على Windows بعد تثبيت Tailscale وتسجيل الدخول. يفحص السكربت أن المنفذ غير مستخدم لخدمة أخرى، ثم ينسخ `.env` احتياطياً ويضبط `SPY_IMAGE_PUBLIC_BASE_URL`؛ هذا يعرّض خادم اللعبة على الإنترنت، لذا لا تشغّله إلا إذا أردت الرابط العام الدائم. يمكن بدلاً منه تثبيت [cloudflared لويندوز 64-bit](https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe) ووضعه في `.nexca/cloudflared.exe` أو ضبط `CLOUDFLARED_PATH`. Quick Tunnel مؤقت ويتغير رابطه بعد إعادة تشغيله. ولرابط دائم عبر استضافة عامة، اضبط `SPY_IMAGE_PUBLIC_BASE_URL` على عنوان HTTPS عام لخادم البوت. الأوامر: `/قواعدرسم` و`/حالةرسم` و`/نتائجالرسم` و`/إلغاءرسم`. تُنشأ جداول اللعبة تلقائياً عند التشغيل أو عبر `npm run db:setup`.

### لعبة فيجن

ابدأ في المجموعة بكتابة `فيجن`، ثم سجّلوا بالتفاعل مع رسالة التسجيل (4-12 لاعباً). هذا طور الأدوار؛ طور الرسم في اللعبة الأصلية منفصل ويقبل 4-8 لاعبين. توزّع الأدوار والفصائل عشوائياً وتصل بطاقتك سراً في الخاص. أدوار الشرطي والمراقب والمحقق والمتتبع وصاحب الفخ والوشاش والمستفز يمكن أن تكون مع الأخيار أو الأشرار. كل ليلة تُنفّذ القدرات سراً بالرد على بطاقة القدرة التي يرسلها البوت في الخاص، ثم يعلن البوت الموتى في الصباح، يليه التصويت بالرد على بطاقة التصويت. لا تُقبل أوامر `/fa` أو `/fvote` المباشرة. أعلى الأصوات يطرد اللاعب؛ التعادل لا يطرد أحداً. أوامر المجموعة: `/قواعدفيجن` و`/feignplayers` و`/feignstatus` و`/feignleave` و`/feigncancel`؛ ويمكن استخدام `/feignrole` لإعادة إرسال الدور.

الأدوار: الطبيب ينقذ هدفه من الموت الليلي؛ المجنون يظن أنه دور بريء آخر، ولا تؤثر أفعاله في اللعبة لكنه قد يتلقى نتائج مضللة، ولا يعرف حقيقته حتى النهاية؛ القاتل الأساسي يختار ضحية الأشرار. المنظف يخفي دور من يموت ليلاً، والمزور يغيّر الدور المعلن لمن يموت ليلاً أو يُطرد نهاراً. الشرطي يمنع لاعباً من استخدام قدرته، والمراقب يعرف عدد زوار الهدف، والمحقق يرى احتمالين لأحدهما دوره الحقيقي، والمتتبع يعرف وجهة هدفه، وصاحب الفخ يعطّل زائراً عشوائياً، والوشاش يكشف لك وحدك دور هدفه ويسترد قدرته إذا مات الهدف ليلاً، والمستفز يضع صوتين ضد هدفه ويسترد قدرته إذا مات الهدف ليلاً. الناجي يحمي نفسه حتى ثلاث مرات، والمفجر يزرع ديناميتاً ويفجّر ما زرعه، والسفاح والحرامي والمطارد والساحر يستخدمون قدراتهم كذلك. كل قدرة تُنفّذ فقط بالرد على بطاقة القدرة المناسبة من البوت؛ أوامر القدرة المباشرة لا تُقبل.

يفوز الأخيار بعد القضاء على الأشرار والقتلة المنفردين، ويفوز الأشرار عند بلوغ نصف الأحياء أو أكثر. يفوز السفاح والمفجر والساحر بالانفراد بالبقاء، ويفوز المطارد عند طرده بالتصويت. أدوار اللعبة مستندة إلى [صفحة Feign الرسمية على Steam](https://store.steampowered.com/app/1436990/Feign/) و[دليل الأدوار في مجتمع Steam](https://steamcommunity.com/sharedfiles/filedetails/?id=2640380608)؛ القاتل الأساسي وتنفيذ التفاعل عبر Messenger تكييف خاص بالبوت. يمكن ضبط الحدود والمؤقتات عبر `FEIGN_MIN_PLAYERS` و`FEIGN_MAX_PLAYERS` و`FEIGN_LOBBY_SECONDS` و`FEIGN_NIGHT_SECONDS` و`FEIGN_DISCUSSION_SECONDS` و`FEIGN_VOTING_SECONDS`. تُنشأ جداول اللعبة تلقائياً عند التشغيل أو عبر `npm run db:setup`.

### لعبة المستذئب (Werewolf)

ابدأ في المجموعة بكتابة `ذئب` أو `مستذئب`؛ يُسجّل المضيف تلقائياً. ينضم الآخرون بالتفاعل مع رسالة التسجيل أو بكتابة `/انضمذئب` (4-8 لاعبين). توزّع الأدوار سراً في الخاص: المستذئبون، القرويون، العرّاف، الساحرة، والصياد؛ وعند 8 لاعبين يُضاف كيوبيد ليختار عاشقين في الليلة الأولى، ويموت أحدهما إذا مات الآخر. قبل الليلة الأولى ينتخب اللاعبون عمدةً بالرد على بطاقة التصويت؛ صوته يُحتسب بصوتين. يمكن للعمدة تسمية خليفة بالرد على بطاقة التعيين. تتناوب الليالي السرية مع تقرير صباحي ونقاش وتصويت سري؛ التعادل لا يخرج أحداً. كل اختيار ليلي أو تصويت أو طلقة صياد يجب أن يكون رداً على بطاقة البوت المناسبة؛ لا تُقبل أوامر `/wa` أو `/wvote` أو `/whunt` أو `/whandoff` مباشرة. أوامر المجموعة: `/قواعدذئب` و`/werewolfplayers` و`/werewolfstatus` و`/انضمذئب` و`/werewolfleave` و`/werewolfcancel`. يفوز القرويون عند خروج كل الذئاب، والذئاب عند مساواتهم بقية الأحياء أو تجاوزهم؛ وإذا كان العاشقان من فريقين مختلفين، يستمر اللعب حتى يبقيا وحدهما فيفوزا معاً. هذه نسخة Messenger آلية مستوحاة من [The Werewolves of Miller's Hollow](http://lesloupsgarous.free.fr/) و[ملخص القواعد](https://www.ultraboardgames.com/the-werewolves-of-miller's-hollow/game-rules.php). لم أضف الفتاة الصغيرة لأن قدرتها تعتمد على التلصص الجسدي، ولا اللص لأن دوره يتطلب بطاقتين إضافيتين وتبديل الأدوار قبل الليلة الأولى. أعداد اللاعبين ثابتة بين 4 و8؛ ويمكن ضبط المؤقتات عبر `WEREWOLF_LOBBY_SECONDS` و`WEREWOLF_NIGHT_SECONDS` و`WEREWOLF_DISCUSSION_SECONDS` و`WEREWOLF_VOTING_SECONDS` و`WEREWOLF_HUNTER_SECONDS`.

يستخدم توليد القضايا نموذجاً مخصصاً لهذه اللعبة من حيث التعليمات والتحقق، وليس نموذجاً مدرّباً من الصفر. يعمل Cloudflare Workers AI افتراضياً عبر `CRIME_AI_PROVIDER=cloudflare` وبالإعدادات المشتركة مع شات جود؛ ويمكن تخصيص النموذج عبر `CRIME_AI_MODEL`. تُحفظ القضية في قاعدة البيانات، ويُتحقق من بنية المشتبه بهم والأدلة وكون كريم هو الضحية، كما تُرفض الحبكات المكررة. إذا فشل التوليد، يستخدم البوت قضية احتياطية غير مستخدمة إن وجدت. يمكن اختيار Groq عبر `CRIME_AI_PROVIDER=groq` ومفتاح `GROQ_API_KEY`، أو Gemini عبر `CRIME_AI_PROVIDER=gemini` ومفتاح من [Google AI Studio](https://aistudio.google.com/app/apikey) في `GEMINI_API_KEY`. لتعبئة المخزون يدوياً، أرسل للبوت في الخاص `/تجهيزقضايا` (5 قضايا) أو `/تجهيزقضايا 8` (الحد الأقصى 10). لا يرسل البوت مصادر أو روابط في رسائل اللعبة.

#### مكتبة أنماط القضايا الاختيارية

يمكن تغذية مولّد القضايا ببنية عامة مستخلصة من صفحات ويكيبيديا، من دون إدخال نصوصها أو أسماء أشخاص حقيقيين في اللعبة. الاستيراد يدوي، ويُرسل نص الصفحة العامة إلى مزوّد القضايا المحدد لاستخراج بطاقة عربية مختصرة؛ تُخزّن البطاقة المجردة ورابط المصدر فقط، وتبقى غير معتمدة إلى أن يراجعها المشرف. لا تستورد معلومات خاصة أو قضايا حديثة/غير محسومة. لا تعتمد بطاقات تحتوي تفاصيل تعريفية أو تعليمات تنفيذية. لتهيئة مكتبة الأنماط في قاعدة Messenger استخدم:

```powershell
npm run patterns -- import crime-sources.sample.json
npm run patterns -- list --pending
npm run patterns -- approve 3 4
```

يحتوي [crime-sources.sample.json](./crime-sources.sample.json) عناوين صفحات عامة عن الجريمة والتحقيق والأدلة، ويجلبها البرنامج عبر واجهة ويكيبيديا الرسمية. يمكن أيضاً جلب صفحات مفردة عبر `npm run patterns -- wiki "Crime" "Fraud"`؛ اضبط `CRIME_WIKIPEDIA_LANGUAGE=ar` لاستخدام عناوين ويكيبيديا العربية. استخدم `stats` و`reject <id>` لإدارة المكتبة. لقاعدة Telegram المنفصلة أضف `--telegram` قبل الأمر، مثلاً `npm run patterns -- --telegram import crime-sources.sample.json`؛ يجب أن يكون إعداد مزوّد القضايا ومفتاحه في ملف المنصة المناسب (`.env` أو `.env.telegram`). يحفظ `source_ref` رابط كل صفحة للمراجعة والإسناد، انسجاماً مع ترخيص ويكيبيديا CC BY-SA. متغير `CRIME_PATTERNS=0` يعطّل استخدام الأنماط. تُنشأ طاولة الأنماط تلقائياً؛ لا يستخدم المولّد البطاقات حتى اعتمادها.

## الأوامر
لبدء لعبة `مين قتل كريم` في المجموعة استخدم الأمر `جريمة` فقط؛ لم تعد الصيغ القديمة مثل `مين قتل كريم` و`قتل كريم` و`بدء` تبدأ اللعبة. تظهر أسماء حسابات Messenger للاعبين في قوائم المشتبه بهم والتصويت والنتائج، وتُربط بها أسماء الشخصيات داخل نص القضية حتى تبقى هوية اللاعبين واضحة. تتدرج الأدلة الثلاثة من فرصة الوصول أو التوقيت إلى كشف التناقض ثم دليل يربط القاتل بالدافع أو الأثر. قواعدها التفصيلية عبر `/قواعدقتل` (والأمران `/قواعدقتل كريم` و`/قواعدجريمة` ما زالا مدعومين). الأوامر الأخرى: `/لاعبين` `/خروج` `/الغاء` `/تجربة` لاختبار إرسال المجموعة.
في الخاص: صوّت بالرد على بطاقة التصويت برقم اللاعب فقط؛ لا يُقبل التصويت برسالة مستقلة. استخدم `/دوري` لإعادة إرسال الدور، `/قضية` لتوليد قضية تجريبية، `/تجهيزقضايا [عدد]` لتعبئة القضايا الاحتياطية، و`تجربة` لاختبار الإرسال الخاص.


## 🔐 الأمان (تحديث)
- **لا ترفع/ترسل** `.env` أو `appstate.json` أو `e2ee_device.json` أو `mobile_device.json` أو `.nexca/` أو `outbound_frames.log` أو `Fca_Database/` لأي شخص أو أداة.
- الوضع الافتراضي `LOGIN_MODE=appstate`: يسجّل البوت الدخول باستخدام ملف `appstate.json` بجانب `server.js`. احفظ الجلسة المصدّرة في هذا الملف ولا تشاركها أو نسختها الاحتياطية. `APPSTATE_ENCRYPTION_KEY` يشفّر الملف عند ضبطه، وتُكتب الملفات السرية بصلاحيات المالك فقط.
- `LOGIN_MODE=password` و`LOGIN_MODE=auto` متاحان عند الحاجة؛ وضع كلمة المرور يستخدم `FB_EMAIL` و`FB_PASSWORD`، أما `auto` فيفضّل الجلسة المحفوظة ثم بيانات الدخول.
- عند اختيار `facebook-chat-api` قد ينشئ FCA ملفي `e2ee_device.json` و`mobile_device.json`؛ يحتويان بيانات جلسة/مفاتيح خاصة، وهما مستثنيان من Git. احتفظ بنسخة `e2ee_device.json` نفسها بين مرات التشغيل ولا تحذفها أو تشغّل نسختين من البوت باستخدام هوية الجهاز نفسها؛ المفاتيح المرفوعة تعتمد على هذا الملف.
- `services/logRedactor.js` يخفي كلمة المرور والكوكيز ومفاتيح API من كل السجلات.
- **قفل الدخول**: بعد رفض فيسبوك تسجيل الدخول (`checkpoint` / `login_blocked` / `Not logged in`) يُوقف البوت محاولات الدخول مؤقتاً (`.nexca/login-lock.json`) حمايةً للحساب من تكرار المحاولات. أوقف البوت، وراجع إشعارات الأمان وحالة الحساب عبر Facebook مباشرة، وأكمل أي تحقق مطلوب، ثم انتظر انتهاء المهلة قبل إعادة المحاولة. لا تحذف ملف القفل ولا تستخدم `FORCE_LOGIN` لتجاوز الرفض. يعتمد المشروع على واجهة غير رسمية؛ للتكامل المدعوم استخدم واجهات Meta الرسمية.
- حدود إرسال في الدقيقة والساعة واليوم، وقاطع يوقف الإرسال مؤقتاً بعد أخطاء الرفض، وحد رسائل لكل مستخدم، وقائمة مجموعات مسموحة اختيارية. اكتب `إيقاف` أو `stop` في الخاص لإيقاف رسائل البوت، و`ابدأ` أو `start` لإعادتها؛ ويُحفظ الاختيار في `.nexca/safety-state.json`. الإعداد `STRICT_PRIVATE=1` يمنع الخاص قبل أن يبدأ المستخدم المحادثة، ويمكن ضبط `QUIET_HOURS` مثل `3-7` لإيقاف الرسائل في هذه الساعات.

## 🖼️ الصور
تُرسل الصورة عبر ملف مؤقت بامتداد صحيح (يُفحص محتواها PNG/JPEG/WEBP) مع إعادة محاولة. في الجاسوس: Pixabay بصورة عشوائية من 20 نتيجة، ثم Gemini كبديل، وإن فشل إرسال الصورة للاعب يصله رابط موقّع (إن ضُبط `SPY_IMAGE_PUBLIC_BASE_URL`) أو وصف نصي بدل إلغاء اللعبة. تُكشف الصورة في المجموعة بعد نهاية الجولة.
